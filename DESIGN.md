## 1. Механизм отмены запросов и выбор задержки Debounce

### Механизм отмены (Race Condition Handling)

Для предотвращения состояния гонки (race condition), когда ответ на более ранний запрос приходит позже ответа на актуальный запрос, используется встроенный браузерный API **`AbortController`** (в связке с `AbortSignal`).

## Почему отмена через abort, а не флаг «актуален ли ответ»

Флаг (например, `if (requestId !== latestId) return`) только **игнорирует** устаревший ответ, когда тот уже пришёл. Сам запрос при этом продолжает выполняться:

- браузер всё равно скачивает ответ и держит соединение занятым;
- сервер всё равно выполняет работу;
- во вкладке Network все старые запросы выглядят завершёнными, поэтому отмену нельзя проверить;
- каждое место, где обрабатывается ответ, должно помнить о проверке флага. Достаточно забыть один раз, и гонка запросов возвращается.

`AbortController.abort()` отменяет запрос **в источнике**: `fetch` останавливается, соединение освобождается, DevTools показывает запрос как _(canceled)_, а промис `fetch` отклоняется с `AbortError`. Эта ошибка классифицируется как `'aborted'` и никогда не показывается пользователю (`classifyError` / `shouldShowError` в `src/core/classify-error.ts`). Контроллер отменяет предыдущий запрос на **каждое событие ввода**, ещё до debounce (обработчик `input` в `src/main.ts`, `cancel()` в `src/core/search-controller.ts`).

- **Как это работает:** Перед инициацией каждого нового HTTP-запроса контроллер проверяет наличие активного предыдущего запроса и вызывает `abortController.abort()`. Сигнал передаётся в `fetch` (или HTTP-клиент).
- **Преимущества решения:**
  1. **Гарантия консистентности UI:** Устаревшие ответы гарантированно отбрасываются на уровне сетевого слоя и никогда не перезапишут актуальное состояние.
  2. **Экономия ресурсов:** Браузер физически разрывает сетевое соединение, снижая нагрузку на сеть клиента и сервер.
  3. **Отсутствие утечек памяти:** Прерванные промисы обрабатываются через перехват ошибки `AbortError`.

### Выбор задержки Debounce

Для минимизации количества лишних сетевых запросов при быстром вводе текста пользователем применяется техника **debounce** с задержкой **`300 мс`**.

- **Обоснование значения (`300 мс`):**
  - Средняя скорость печати пользователя составляет около 200–250 символов в минуту (примерно 1 символ каждые 240–300 мс).
  - Задержка в **300 мс** является оптимальным компромиссом между UX и производительностью: она достаточно велика, чтобы отфильтровать промежуточные нажатия клавиш при вводе слова, но достаточно мала, чтобы интерфейс ощущался отзывчивым и мгновенным (порог восприятия задержки человеком как «немедленной реакции» находится в районе 100–300 мс).

## Задержка debounce: почему 300 мс и что будет, если её изменить

300 мс — распространённый компромисс. Это больше обычной паузы между нажатиями клавиш (~100–200 мс), поэтому слово, набранное без остановок, порождает один запрос. И это достаточно мало, чтобы после остановки ввода результат появлялся почти сразу.

- **Если debounce убрать (0 мс):** каждое нажатие клавиши отправляет запрос. Ввод «germany» даёт 7 запросов, 6 из них отменяются. Результат остаётся правильным, потому что отмена не допускает устаревших ответов, но тратятся сеть и ресурсы сервера, а индикатор загрузки мерцает.
- **Если задержку сильно увеличить (например, 2000 мс):** запросов становится меньше, но приложение кажется зависшим: после остановки ввода 2 секунды ничего не происходит.

## 2. Анализ алгоритмической сложности (Big O)

## Big O

Обозначения: L — число языков одной страны, C — число валют одной страны, N — число стран в ответе API.

### `mapCountryResponse(raw)` — `src/core/mapper.ts`

Функция принимает **один объект** страны, а не массив.

- `name`, `region`, `population` — чтение поля, O(1).
- `flag: raw.flags?.svg ?? raw.flags?.png ?? ''` — до двух проверок, O(1).
- `capital: raw.capital ?? null` — `capital` в API это строка, чтение поля, O(1).
- `languages: raw.languages?.map((lang) => lang.name) ?? []` — один проход по массиву языков, O(L).

Итого: **O(L)** по времени и **O(L)** по памяти (новый массив названий языков).
L мало (у страны не больше ~16 языков), поэтому на практике функция работает за O(1).

## 3. Принципы чистого кода (Clean Code)

В процессе разработки были применены следующие принципы проектирования и чистого кода:

1. **Single Responsibility Principle (Принцип единственной ответственности — SRP):**
   - **Где применено:** Разделение логики на изолированные слои/модули:
     - `SearchController` — отвечает исключительно за управление состоянием поиска.
     - `searchCountries` — отвечает только за сетевое взаимодействие и передачу `AbortSignal`.
     - `mapCountryResponse` — чистая функция, отвечающая исключительно за трансформацию DTO (Data Transfer Object) в модель представления.

2. **Pure Functions & Immutability (Чистые функции и иммутабельность):**
   - **Где применено:** Функция `mapCountryResponse` не мутирует исходный массив и объекты ответа от сервера, а возвращает новые структуры данных. При одинаковых входных данных она всегда возвращает идентичный результат без побочных эффектов (side effects), что упрощает её модульное тестирование.

3. **Explicit Error Handling (Явная обработка ошибок и разделение исключений):**
   - **Где применено:** В блоке `try / catch` контроллера поиска явно разделена обработка отмены запроса (`if (controller.signal.aborted)`) и реальных сетевых/серверных ошибок. Отмена запроса не считается ошибкой приложения и не показывает пользователю сообщение о сбое.

4. **Meaningful Naming & Self-Documenting Code (Осмысленное именование):**
   - **Где применено:** Использование говорящих имен переменных, констант и методов (`SEARCH_DELAY_MS`, `controller`, `mapCountryResponse`), что избавляет от необходимости писать избыточные комментарии для объяснения базовой логики.

5. **DRY (Don't Repeat Yourself) & Guard Clauses (Ранний возврат):**
   - **Где применено:** В начале функции поиска используются защитные условия (guard clauses) для проверки пустой или состоящей из пробелов строки (`if (query.trim() === '')`), что предотвращает лишние вызовы API и уменьшает уровень вложенности кода (`if/else`).
